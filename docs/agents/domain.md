# Domain docs

## Layout

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root defines domain terms.
- `docs/adr/` contains architecture decision records.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.
If they do not exist, continue silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a needed term is absent, reconsider the wording or record the gap
for domain-modeling.

## Decision conflicts

Explicitly identify any proposal that contradicts an existing ADR.
Name the ADR and explain why the decision should be reconsidered.
